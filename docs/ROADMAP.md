# 방향과 이슈 처리 기준

## 지향

- **주문 생산 소기업의 견적→주문→작업지시→출하 흐름**을 한 화면 흐름으로 잇는다.
- **설치가 쉬워야 한다**: 폴더 복사 + 더블클릭. 외부 패키지·빌드·클라우드 계정 없음.
- **작게 유지한다**: 서버 한 파일, 화면 한 파일. 직원이 읽고 고칠 수 있는 크기.
- **계산은 서버만, 입력은 믿지 않는다**: 금액·세액은 서버가 계산, 화면 출력은 전부 이스케이프.
- 업종 차이는 코드가 아니라 `presets/*.json`으로.

## 이슈 처리 절차

1. 새 이슈를 확인하고 재현 또는 필요성을 검토한다.
2. 아래 기준으로 **수락 / 보류 / 거절**을 정하고 **이유를 이슈에 적는다**.
3. 수락한 것은 테스트와 함께 수정하고, 결과(무엇을 바꿨나, 테스트 결과, 남은 한계)를 이슈에 남기고 닫는다.

| 판정 | 기준 |
|---|---|
| 수락 | 재현되는 버그, 보안 문제, 현장 불편을 줄이는 작은 기능, 위 지향과 맞는 것 |
| 보류 | 필요해 보이나 근거(실제 사용 사례)가 부족, 범위가 커서 쪼개야 함, 추가 정보 필요 |
| 거절 | 외부 의존성이 크게 늘어남, 세금 신고·회계 대행처럼 법적 경계를 넘는 기능, 다중 회사 클라우드(현재 범위 밖), 작게 유지하는 원칙과 충돌 |

- 세션 유지(재시작 후에도 로그인 유지)
