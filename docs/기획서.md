# 제조 소기업 MES (가칭 "공장 한 창") 기획서

기획·설계·합격기준·검증 결과를 이 문서 한 곳에서 관리한다. 기준일 2026-10-26.

## 1. 영상 분석 (오토프로그, "외주 없이 사장이 직접 만든 MES")
직원 7명 안팎의 허니콤보드 제조사가 사장 주도로 AI(Claude)와 만들어 6~7개월 쓴 사내 시스템이다.

| 영상에서 확인된 기능 | 직원이 말한 효과 |
|---|---|
| 견적서: 품목 번호만 넣으면 자동 계산, 고객사 메일로 바로 발송 | 구글시트 수작업 계산·재검토 사라짐 |
| 견적 → 주문 한 번에 변환(사업자등록증 첨부·배송 일정·결제 확인이 주문서에 내장) | 단계 3~4개 축소 |
| 작업지시서를 종이 대신 현장 화면으로, 작업 파일 일괄 배포 | 작업 빨라짐, 불량·출하 누락 감소 |
| 배송 캘린더(작업됨·출하준비·진행 중 상태) | 엑셀로 날짜 찾던 일 사라짐 |
| 일 부하 간트 차트 | 일이 몰리는 날을 눈으로 보고 배분 |
| 업무관리(기한순 정렬, 팀 공유) | 수기 메모로 놓치던 일 감소 |
| 불편하면 직원이 직접 고쳐 쓰는 구조 | 현장 요청이 바로 반영 |
| AI 컨셉컷, 블로그 자동화 | 촬영 3시간 → 30분 (이번 범위 밖) |

핵심 교훈 두 가지. ① 대단한 기능이 아니라 **견적→주문→작업지시→출하가 한 화면 흐름으로 이어지는 것**이 효과의 전부다. ② 성공 요인은 **사장 한 명이 AI를 잘 다루고 직원에게 전파**한 것인데, 대부분의 소규모 공장에는 그 사람이 없다. 그래서 우리는 이 흐름을 **설치만 하면 돌아가는 제품**으로 만든다.

## 2. 타깃과 문제
- 타깃: 직원 3~30명, 주문 생산(견적→주문→생산→출하) 제조 소기업. 금속가공·인쇄·패키지·목공·식품 소량생산 등.
- 현재 상태: 엑셀·구글시트·종이 작업지시서·카톡. IT 담당 없음, ERP는 비싸고 무겁다.
- 문제: 견적·주문서 재입력, 종이 분실, 납기 지연 발견이 늦음, 일이 몰리는 날을 모름, 출하 누락.

## 3. 범위
**포함(MVP)**: 거래처·품목 / 견적(자동계산·메일·인쇄) / 견적→주문 변환 / 작업지시(현장 화면, 공정 단계, 파일 첨부) / 출하 캘린더 / 일 부하 간트 / 업무관리(팀 공유) / 오늘 화면(지연·임박·미결제·무회신 견적) / 개선요청함 / 업종 프리셋 / CSV 내보내기 / 백업 / 사용자 3권한.

**제외(이유)**: 재고·BOM 자재 소요(2단계, 먼저 흐름부터), 회계·세금계산서 발행(세무사법·홈택스 연동이 얽혀 있어 범위 밖), AI 이미지·블로그(제조 핵심 흐름 아님), 모바일 앱 스토어 앱(브라우저로 충분), 클라우드 SaaS 다중 회사(1단계는 회사별 설치).

## 4. 설계
- **배포 형태**: 회사 PC 한 대에 폴더를 복사하고 `실행.bat` 더블클릭. 같은 사무실 PC·공장 태블릿·폰이 브라우저로 접속(`http://PC주소:8780`). 설치할 외부 패키지 0개(Python 표준 라이브러리 + SQLite). 클라우드 계정·월 서버비 없음.
- **업종 프리셋**: 공정 단계·단위·업무 분류 색을 JSON으로 둔다(`presets/`). 최초 설정에서 고르고 설정 화면에서 고친다. 새 업종은 코드 수정 없이 JSON 추가.
- **권한**: 관리자(전부+사용자·설정·백업) / 사무(견적·주문·거래처·품목·업무) / 현장(주문·작업지시 보기, 공정 단계 변경, 파일 받기, 업무·개선요청). 직원은 이름 + PIN으로 로그인.
- **계산은 서버만**: 견적·주문 금액은 서버가 품목 수량·단가로 계산한다. 화면이 보낸 합계는 무시한다.
- **데이터 모델**: users, customers, items, quotes(lines JSON), orders(lines JSON·stage·hours·due·paid), files, tasks, feedback, log.
- **화면**: 오늘 / 견적 / 주문 / 현장 / 캘린더 / 부하 / 업무 / 거래처·품목 / 개선요청 / 설정. 휴대폰(390px)·태블릿·PC 반응형. 현장 화면은 큰 글씨·큰 버튼.
- **보안**: PIN은 PBKDF2 해시, 세션 쿠키(HttpOnly·SameSite=Strict), 로그인 5회 실패 잠금, 모든 API 인증, 업로드 이름·크기 제한, 화면 출력 전부 이스케이프. 메일 비밀번호는 `data/config.json`에 평문이므로 폴더 접근 권한이 곧 보안 경계다(문서에 명시).
- **유지보수**: 서버 한 파일(`server.py`) + 화면 한 파일(`static/index.html`). 영상의 "불편하면 직접 고쳐 쓴다"를 위해 일부러 작게 유지하고, 개선요청함으로 요청을 모은다.

## 5. 합격 기준 (구현 전에 고정, 테스트 `test_mes.py`로 검증)
| # | 기준 |
|---|---|
| AC1 | 최초 설정으로 관리자·프리셋이 생기고, 이후 설정 재호출은 거절된다 |
| AC2 | 로그인 없이 모든 API는 401, 틀린 PIN 거절, 5회 실패 시 잠금 |
| AC3 | 현장 권한은 견적·거래처 쓰기 403, 공정 단계 변경은 허용 |
| AC4 | 견적 금액은 서버 계산(클라이언트 합계 무시), 부가세 10% |
| AC5 | 견적→주문: 납기·배송지 필수, 사업자등록증 미확인 거래처는 확인 없이 409 |
| AC6 | 공정 단계는 목록 안의 값만, 변경 이력 기록, 마지막 단계면 완료 처리 |
| AC7 | 오늘 화면의 지연·임박·미결제·무회신 견적 계산이 정확 |
| AC8 | 부하 합계 = 진행 주문 시간 합계, 주말 제외 분배, 용량 초과 표시 |
| AC9 | 파일 업로드·다운로드 동작, 경로 탈출 불가, 크기 제한 |
| AC10 | 메일: 설정 없으면 명확한 오류, 설정되면 발송 후 상태 발송됨 |
| AC11 | CSV 내보내기가 엑셀 한글 깨짐 없음(BOM) |
| AC12 | 백업 다운로드와 시작 시 자동 백업(14개 유지) |
| AC13 | `<script>` 이름이 인쇄·화면에서 이스케이프 |
| AC14 | UI 스모크: 390px·PC 렌더, 콘솔 오류 0, 핵심 흐름 클릭 통과 |
| AC15 | 외부 패키지 0, `실행.bat` 한 번으로 기동 |

## 6. 위험과 사용자 과제
| 항목 | 내용 |
|---|---|
| 유통 | 영상 속 회사는 사장이 직접 해서 됐다. 일반 공장은 **설치·초기 입력·교육**이 팔리는 것이다. 설치 대행 + 연 유지보수 패키지가 현실적 |
| 초기 데이터 | 거래처·품목 엑셀을 CSV로 가져오는 기능은 2단계(현재는 내보내기만) |
| 단일 PC 서버 | PC가 꺼지면 접속 불가. 백업 폴더를 NAS·USB에 복사하는 습관 필요 |
| 실제 공장 검증 | 가상 데이터로만 검증. 1~2개 공장 시범 운영이 다음 단계 |
| 메일 | 회사 메일 SMTP 정보 필요(네이버·구글 앱 비밀번호 등) |

## 8. 검증 결과
- 서버 테스트 14건 통과(`py test_mes.py`): AC1~AC13 전부 + 입력 검증·권한 경계·남의 업무 보호·마지막 관리자 보호·다른 출처 요청 거절.
- 테스트 중 찾아 고친 것: 부하 합계 비교가 하루 단위 반올림 오차(0.11시간)로 실패 → 오차 허용 범위를 명시. 처음 접속할 때 로그인 확인이 401 오류를 남기던 점 → 상태 조회에 로그인 사용자를 함께 돌려줘 오류 제거.
- UI 스모크(AC14): 가상 데이터(공장 1곳, 주문 5건)로 PC·휴대폰(375px) 확인. 10개 탭 모두 가로 넘침 0, 견적 작성 → 주문 변환 → 공정 변경 → 작업지시서 인쇄 → 현장 권한 로그인(메뉴 7개, 현장 화면) 통과.
- 외부 패키지 0, `실행.bat` 포함(AC15).
- **재점검(2026-10-26, 2차)** — 서버 코드를 다시 읽고 적대 입력 17종을 추가 테스트(`test_adversarial`)해 찾아 고친 것:
  - 처리되지 않은 예외(설정 포트에 글자, 부하 일수에 글자, 공정 목록이 배열이 아님 등)가 나면 서버가 응답 없이 연결을 끊었다 → 모두 400 또는 500 JSON으로 응답.
  - 이름 칸에 배열·객체를 보내면 `['a']` 같은 문자열로 저장됐다 → 입력 형식 오류로 거절.
  - 견적 수정 시 없는 거래처 번호를 넣으면 DB 오류(500) → 400 "거래처를 선택하세요".
  - 메일 제목에 회사명이 들어가므로 회사명에 줄바꿈이 있으면 메일 헤더가 추가될 수 있었다 → 줄바꿈 제거. SMTP 포트 범위(1~65535) 검사.
  - Content-Length가 음수·글자면 서버가 멈추거나 끊겼다 → 400.
  - 로그인 실패 기록이 무한히 쌓일 수 있었다 → 상한.
  - 테스트 15건 통과. UI 재확인: 10개 탭 PC(800px·1024px)·폰(375px) 가로 넘침 0, 파일 업로드 클릭 흐름(올리기→목록 표시) 통과, 콘솔 오류 0.
- 알려진 한계(재점검에서 확인): 서버를 재시작하면 모두 다시 로그인해야 한다(세션이 메모리에만 있음). 틀린 PIN 5회로 다른 사람의 이름을 1분 잠글 수 있다(사내망 전제로 허용). 백업 폴더는 같은 PC 안에 있어 PC 고장 시 함께 잃는다.
- **실제로 확인하지 못한 것**: 실제 SMTP 서버 발송(가짜 발송기로만 검증), 실제 공장 현장 사용, 여러 PC 동시 접속 부하, 파일 업로드 화면 클릭(API는 테스트됨).

## 9. 설치·운영 안내
1. 서버로 쓸 PC에 Python 3.10 이상을 설치한다(설치 시 "Add to PATH" 체크).
2. `제조MES` 폴더를 통째로 복사하고 `실행.bat`을 더블클릭한다. 브라우저가 열리면 처음 설정(회사명·업종·관리자)을 한다.
3. 다른 PC·태블릿·폰은 같은 와이파이에서 `http://서버PC의IP:8780` 으로 접속한다. 윈도우 방화벽 허용 창이 뜨면 허용한다.
4. 설정 화면에서 직원 계정(권한 3종)과 견적 메일 서버를 입력한다.
5. 데이터는 `data/` 폴더에 있다. 이 폴더를 주기적으로 USB·NAS에 복사한다(자동 백업은 `data/backup/`).
6. 보안: 외부 인터넷에 직접 열지 않는다(사내망 전용). 외부 접속이 필요하면 VPN을 쓴다. `data/config.json`에 메일 비밀번호가 평문으로 있으니 폴더 접근을 제한한다.
